## 2. 为什么不使用赛道状态机

赛题地图是一条没有岔路的连续闭合黑线：

- AB、CD 直线各 1.5 m；
- BC、DA 为半径 0.5 m 的半圆；
- 黑线宽度 1.8±0.2 cm；
- A 点存在一条长 5 cm、与环线垂直的启停黑线。

因此当前程序不判断“正在直线还是弯道”，也不按编码器里程切换 AB/BC/CD/DA 状态。全程使用同一套灰度循迹控制，只保留：

1. 等待板载 K 键发车；
2. 离开起点后再次检测到 A 点横线停车；
3. 20 s 到时强制停车。

## 3. 循迹算法

8 路探头从 S1 到 S8 的权重为：

```text
-8, -6, -3, -1, +1, +3, +6, +8
```

检测到黑线的通道参与加权平均，得到 `error`。控制量采用成功工程的逻辑：

```text
difference = 35 × error
left_speed  = 80 + difference
right_speed = 80 - difference
```

其中：

- `35 × error` 是灰度位置比例修正；
- 偏差已经出现但差速太小时，强制加入最小差速，以克服四驱机械耦合的转向死区；
- 丢线、全白或全黑时不继续使用旧位置偏差，左右恢复基础速度；
- 当前先保持纯灰度对照，不让 IMU 阻尼削弱弯道差速。

### 与成功工程一致的连续差速

```c
difference  = 35 * error;
left_speed  = 80 + difference;
right_speed = 80 - difference;
```

基础速度 80 对应 40% PWM，与参考工程实际主循环的 `Track_PID_Compute(80.0f, ...)` 一致。`difference` 与参考工程一样限制在 `-160~160`，不再使用 `|E|>=3` 的人为切换阈值，也不使用 180 ms 反转计时。典型输出如下：

| 灰度偏差 | 外侧 PWM | 内侧 PWM |
|---:|---:|---:|
| `|E|=1~2` | 80% 正转 | 0% |
| `|E|=3` | 约 92.5% 正转 | 约 18% 反转（受最小占空比约束） |
| `|E|=4` | 100% 正转 | 约 30% 反转 |
| `|E|>=5` | 100% 正转 | 最大约 40% 反转 |

右转时左侧为外侧、左转时右侧为外侧。只要边缘偏差仍存在，负 PWM 就随偏差连续保持，不会在最外侧探头检测到黑线前提前超时。基础居中巡航为 40%。

电机驱动采用安全换向顺序：检测到正转与反转直接互换时，先关闭四个电机的正反 PWM，保持 1 ms 全零输出（2 个完整 PWM 周期），再开启目标方向。该延时只在方向翻转时发生，同方向调速和正常巡航不受影响。

当前没有积分项和陀螺仪项，控制核心是与参考成功代码位置环一致的灰度 P 控制。

## 4. A 点终点识别

按键发车时不会立即把起点当成终点。程序必须依次满足：

1. 发车超过 500 ms；
2. 曾经检测到黑线数量不超过 2 路，确认已离开 A 横线；
3. 发车至少 6 s；
4. 再次连续 6 次检测到至少 4 路黑线。

满足后输出 `FINISH_A` 并停止全部电机。如果 20 s 内没有识别到 A 点，则输出 `TIMEOUT_STOP` 并停车。

注意：首次实机必须确认 A 横线经过时确实稳定出现 `N>=4`。若车体安装高度或灰度板宽度变化，应根据串口数据调整 `FINISH_BLACK_MIN`，不能直接假定已经验证。

## 5. 接线和固定引脚

### 灰度传感器

| 模块 | STM32F407 | 说明 |
|---|---|---|
| SDA | PC2 | 软件 I2C，开漏 |
| SCL | PC3 | 软件 I2C，开漏 |
| VCC | 按模块额定电压接 | 与 MCU 共地 |
| GND | GND | 必须共地 |

传感器地址为 `0x4C`，程序使用 `0xAA` 握手、`0xDD` 读取 8 位数字掩码。bit0~bit7 对应 S1~S8，1=白、0=黑。

当前 `gray.c` 已按“循迹成功最终版”的软件 I2C逐项改写为标准库版本：

- PC2/PC3 配置为开漏输出并启用内部上拉；
- 固定 200 次空循环形成约 5 us 时序；
- 每帧执行 `START→写地址→0xDD→重复START→读地址→1字节→NACK→STOP`；
- 上电最多进行50次 `0xAA/0x66` 握手；
- 不再使用此前额外加入的 SCL等待、9时钟恢复和三次事务重试，以便与成功工程直接对照。

本版本启动串口标识必须是：

```text
H60 H-TRACK SPL, GRAY_REF_I2C, NO_GYRO
```

若仍出现 `H60 H-MAP TRACK` 或 `MAP,MS=...`，说明烧录的仍是旧工程固件。

### HC-05 蓝牙串口

| HC-05 | STM32F407 |
|---|---|
| RXD | PB10 / USART3_TX |
| TXD | PB11 / USART3_RX |
| GND | GND |

串口参数：115200，8 数据位，1 停止位，无校验。

### 板载器件

| 功能 | 引脚 | 有效电平 |
|---|---|---|
| K 键 | PE1 | 按下为低 |
| 蜂鸣器 | PE0 | 低电平关闭 |
| QMI8658A SCL | PB6 / I2C1_SCL | 板载 |
| QMI8658A SDA | PB7 / I2C1_SDA | 板载 |

### 四路电机

用户实机确认的轮位：

| 名称 | 物理轮位 | PWM 引脚 | 前进输出 |
|---|---|---|---|
| MA | 右后 | PE9 / PE11，TIM1 CH1/2 | MA2 |
| MB | 左后 | PE13 / PE14，TIM1 CH3/4 | MB1 |
| MC | 右前 | PE5 / PE6，TIM9 CH1/2 | MC2 |
| MD | 左前 | PB14 / PB15，TIM12 CH1/2 | MD1 |

8 路电机 PWM 均为 2 kHz，比较值范围 0~999。

## 6. 蓝牙串口输出

运行数据每 200 ms 输出一次：

```text
RUN,MS=...,M=0x..,N=...,E=...,G=...,L=...,R=...,PL=...,PR=...,I2C=...,IMUE=...
```

- `MS`：本次运行时间；
- `M`：8 路灰度原始位掩码；
- `N`：检测到黑线的通道数；
- `E`：加权位置偏差，负=线偏左，正=线偏右；
- `TM`：控制模式，R=右侧已经产生负 PWM、L=左侧已经产生负 PWM、C=两侧均为正转或居中；
- `G`：陀螺仪 Z 轴角速度；
- `L/R`：算法给出的左右逻辑速度；
- `PL/PR`：最终左右 PWM 比较值；
- `I2C`：灰度通信状态，1=成功；
- `GE`：灰度读取经过 3 次重试后仍失败的累计次数；
- `GS`：参考驱动事务失败阶段，1=写地址 NACK、2=命令 NACK、3=读地址 NACK；
- `IMUE`：IMU 累计通信错误次数。

## 7. 首次实机验证顺序

1. 先架空车轮，只给主控和传感器供电。
2. 打开蓝牙串口，复位后确认出现 `GRAY=1`；`IMU=1` 最好也成立。
3. 不按 K 键，用白纸、黑线分别遮挡 S1~S8，确认 `M`、`N` 和 `E` 的方向。
4. 将车放在 A 点，车头朝 A→B（顺时针方向）。
5. 架空状态按 K 键，确认 MA、MB、MC、MD 都是物理前进方向。
6. 立即复位停车，再落地低风险试跑。
7. 首轮重点保存弯道前后和回到 A 点的数据，不要先调参数。

如果 `E>0` 时车辆反而向左修正，说明传感器 S1~S8 的物理左右顺序与代码相反，应反转权重或通道顺序，不能用盲目增大 Kp 掩盖。
