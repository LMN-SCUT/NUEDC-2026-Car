# K230 与 STM32F407 通信协议 v1

## 1. 目标

本协议用于视觉观测链路：
- K230 发送目标观测量和状态位。
- F407 接收后执行融合控制与舵机输出。
- 协议强调抗干扰、防误动作、可扩展。

## 2. 物理层建议

- 串口：UART
- 波特率：115200（首版）
- 数据位：8
- 校验位：None
- 停止位：1
- 流控：None

### 2.1 F407 HAL 实现说明

- F407 端采用 HAL 工程重写协议收发与解析。
- 工程路径：[protocol/hal_protocol](protocol/hal_protocol)
- 当前通信接口保持不变：UART4，115200，8N1。

当前 HAL 行为约定：
- RX：UART4 中断逐字节解析。
- TX：每 100ms 发送一帧反馈（FB）。
- ACK：仅对 PARAM 帧返回 ACK（OBS/HB 不回 ACK）。

说明：后续如发现带宽不够，可升到 230400，但需先验证线缆质量和EMI。

## 3. 帧格式

统一帧结构：

| 字段 | 长度 | 说明 |
|---|---:|---|
| SOF1 | 1 | 0xAA |
| SOF2 | 1 | 0x55 |
| Type | 1 | 帧类型 |
| Seq | 1 | 序号，0~255循环 |
| Len | 1 | Payload长度 |
| Payload | Len | 载荷 |
| Checksum | 1 | Sum(Type..Payload)低8位 |

校验公式：
- checksum = (Type + Seq + Len + payload[0] + ... + payload[n-1]) & 0xFF

接收判定：
1. 帧头匹配。
2. Len 合法。
3. Checksum 正确。
4. 超长/异常立即丢弃并重同步帧头。

### 3.1 跨平台结构体对齐约束（必须）

K230 与 F407 端禁止直接使用默认对齐结构体做串口收发，必须使用 1 字节对齐或手动按字节打包。

建议做法：
- GCC/Clang：使用 __attribute__((packed))。
- 或使用 #pragma pack(1) / #pragma pack() 包裹协议结构体。
- 更稳妥方案：发送端按字节序列化，接收端按字节反序列化，不依赖编译器布局。

统一约定：
- 多字节字段均为小端序。
- 协议 Len 以实际字节长度为准，不以 sizeof(struct) 为准。

## 4. 帧类型定义

### 4.1 观测帧（K230 -> F407）

- Type = 0x01

Payload定义：

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| timestamp_ms | uint32 | ms | K230本地时间戳 |
| center_u | int16 | px | 靶心x像素坐标 |
| center_v | int16 | px | 靶心y像素坐标 |
| err_u | int16 | px | 相对视觉零点x误差 |
| err_v | int16 | px | 相对视觉零点y误差 |
| confidence | uint8 | 0~100 | 置信度 |
| target_lost | uint8 | bool | 1=失锁 |
| mode_hint | uint8 | enum | 视觉建议模式 |
| reserved | uint8 | - | 保留 |

Len = 16

当 target_lost = 1 时，字段约定如下：
- err_u = 0
- err_v = 0
- confidence 建议置为 0

说明：失锁时发送零误差可避免旧误差残留驱动控制器。

mode_hint建议：
- 0：普通瞄准
- 1：转弯补偿建议
- 2：同步画圆建议

### 4.2 心跳帧（K230 -> F407）

- Type = 0x02
- 用于确认链路在线。
- 周期：100ms

Payload：

| 字段 | 类型 | 说明 |
|---|---|---|
| timestamp_ms | uint32 | K230时间戳 |
| status_bits | uint16 | bit0=视觉运行, bit1=模型运行, bit2=相机就绪 |

Len = 6

### 4.3 控制反馈帧（F407 -> K230）

- Type = 0x81

Payload：

| 字段 | 类型 | 说明 |
|---|---|---|
| ctrl_state | uint8 | 0=idle,1=track,2=calib,3=failsafe |
| yaw_pwm | uint16 | 当前输出 |
| pitch_pwm | uint16 | 当前输出 |
| fault_code | uint16 | 故障码 |
| lap_phase_q15 | uint16 | 圈进度Q15，0~32767 |

Len = 9

### 4.4 参数下发帧（双向，可选）

- Type = 0x10（K230->F407）
- Type = 0x90（F407->K230 ACK）

用于调参和模式切换，不作为实时闭环主通道。

Payload建议：

| 字段 | 类型 | 说明 |
|---|---|---|
| cmd_id | uint8 | 命令ID |
| arg0 | int16 | 参数0 |
| arg1 | int16 | 参数1 |
| arg2 | int16 | 参数2 |

Len = 7

命令定义建议：
- cmd_id = 0x01：更新PID参数（arg0/arg1/arg2按约定缩放）
- cmd_id = 0x02：切换控制状态（track/calib/failsafe）
- cmd_id = 0x03：一键设为视觉零点

其中 cmd_id = 0x03 用于比赛前快速校准：
- 触发时机：人工将激光点调到靶心后发送。
- 执行动作：F407 读取当前观测 err_u/err_v，写入 offset_u0/offset_v0。
- ACK返回：成功/失败及当前保存的 offset 值。

参数缩放约定（建议）：
- PID参数采用 Q10 定点：实际值 = arg / 1024.0。
- 状态切换 arg0：
	- 0=idle, 1=track, 2=calib, 3=failsafe。

### 4.5 ACK 帧（F407 -> K230）

- Type = 0x90
- 用于确认参数写入或命令执行结果。

Payload建议：

| 字段 | 类型 | 说明 |
|---|---|---|
| ack_code | uint8 | 0=OK, 1=ERR, 2=BUSY |
| cmd_id | uint8 | 对应的命令ID |
| arg0 | int16 | 回传参数0（可选） |
| arg1 | int16 | 回传参数1（可选） |
| arg2 | int16 | 回传参数2（可选） |

Len = 9

建议：
- 对 cmd_id=0x03（一键零点）返回 offset_u0/offset_v0。

说明：
- HAL 版本仅对 PARAM 帧返回 ACK（OBS/HB 不回 ACK）。

### 4.6 故障码（F407 -> K230）

fault_code 建议定义：
- 0x0000 正常
- 0x0001 视觉失锁
- 0x0002 观测帧超时
- 0x0003 串口校验失败过多
- 0x0004 PWM越界被钳位
- 0x0005 校准参数校验失败
- 0x0006 进入 failsafe

## 5. 通信时序与超时

- 观测帧频率：20~50Hz。
- 心跳帧频率：10Hz。
- F407 超时阈值：100ms 未收到观测帧，进入视觉失联保护。
- 300ms 未收到任何帧，进入通信故障保护。

## 6. 防错机制

1. Checksum错误：
- 本帧丢弃，不更新控制量。

2. Seq跳变检测：
- 允许少量丢包。
- 连续异常可记录 fault_code 便于排障。

3. 数据越界保护：
- confidence>100 或像素值越界，判定帧非法。
- target_lost=1 时，禁止积分项继续累积，并清空或快速泄放积分状态（Anti-windup）。
- target_lost=1 时忽略本帧误差闭环量，仅执行 failsafe 或理论角保持。

4. 速率限制：
- F407 对目标PWM设置每周期最大变化量，防止错误帧触发猛转。

## 7. 二进制打包示例

观测帧示例（16字节payload）流程：
1. 写入帧头 0xAA 0x55。
2. 写 Type=0x01, Seq, Len=16。
3. 按小端序写 payload。
4. 累加 Type 到 payload 末字节，取低8位作为 Checksum。
5. 发送整帧。

### 7.1 示例帧（十六进制）

示例：
- Type=0x01, Seq=0x05, Len=0x10
- timestamp_ms=1000
- center_u=320, center_v=240
- err_u=10, err_v=-5
- confidence=90, target_lost=0, mode_hint=0, reserved=0

小端payload：
- E8 03 00 00 40 01 F0 00 0A 00 FB FF 5A 00 00 00

整帧（Checksum按规则计算）：
- AA 55 01 05 10 E8 03 00 00 40 01 F0 00 0A 00 FB FF 5A 00 00 00 6D

## 8. 联调最低通过标准

1. 连续 5 分钟通信无死锁。
2. Checksum 错误帧可被稳定丢弃。
3. 拔插串口后 2 秒内自动恢复数据流。
4. 观测帧中断后 F407 可自动进入 failsafe，不出现舵机暴冲。

## 9. 后续扩展位

- 在 payload 增加目标类型和多目标ID。
- 增加 CRC16 替代 Sum 校验（若现场干扰明显）。
- 增加时间同步帧用于 K230/F407 跨端时钟对齐。

## 10. 与云台例程的兼容与迁移

为兼顾你当前手上的云台例程和后续整车缝合，建议采用“双路径”：

1. 比赛主路径（推荐）：
- 使用本协议二进制帧（K230 -> F407）。
- 由 F407 直接输出 PWM 控制云台。

2. 兼容调试路径（保留）：
- 保留旧例程文本命令语法用于台架调试：
	- #000P1500T0100!
	- {#000P1500T0020!#001P1500T0020!}
- 仅用于调试和回归，不建议作为比赛运行主链路。

兼容约束：
- yaw 对应 ID=000，pitch 对应 ID=001。
- PWM 安全范围统一 500~2497。
- 旧命令 time 字段保持 4 位毫秒（0000~9999）。

实现建议：
- 统一使用 protocol/gimbal_proto.h 与 protocol/gimbal_proto.c。
- 若需要与旧调试工具互通，可调用：
	- gp_format_legacy_servo_cmd()
	- gp_format_legacy_dual_servo_cmd()
